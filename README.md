# Amrutha Varshini — Project Portfolio

A responsive, static portfolio website built with HTML, CSS, and vanilla JavaScript. It can be hosted for free with GitHub Pages.

## Files
- `index.html` — page content and project cards
- `style.css` — colours, layout, responsive styles
- `script.js` — project filters and dynamic year/count

## Personalise it before publishing
Search `index.html` for these placeholders and replace them:
- `YOUR-USERNAME` — your GitHub username
- `YOUR-CV-LINK` — a link to your CV PDF (you can upload the PDF to this repository)
- `YOUR-REPO-LINK-1` through `YOUR-REPO-LINK-6` — each project's GitHub repository URL
- `YOUR-EMAIL@example.com` — your email address
- `YOUR-LINKEDIN` — your LinkedIn profile slug

Also update the project descriptions, titles, technologies, and project categories so every card accurately reflects your work. Remove any starter project that you don't want to showcase.

## Add a project
In `index.html`, copy one complete `<article class="project-card" ...> ... </article>` inside `#project-grid`. Update:
- `data-category`: `data`, `software`, or `research`
- the visual and kicker labels
- title, summary, tech tags, and repository URL

The filter buttons use those three category names. If you add projects, the visible project count updates automatically.

## Publish with GitHub Pages
1. Create a new public GitHub repository, for example `project-portfolio`.
2. Upload `index.html`, `style.css`, `script.js`, and this README to the repository root.
3. Open **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**.
5. Choose branch **main** and folder **/(root)**, then save.
6. Wait a minute or two. GitHub will show your website URL, usually `https://YOUR-USERNAME.github.io/project-portfolio/`.

If you name the repository exactly `YOUR-USERNAME.github.io`, the site URL will instead be `https://YOUR-USERNAME.github.io/`.

## Before you add the link to your CV
- Test every link and make sure none of the `YOUR-...` placeholders remain.
- Check the site on a phone.
- Make sure every project description reflects what you actually implemented.
- Add a short README to each project repository with screenshots, setup instructions, and results.
